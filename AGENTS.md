# Repository Guidelines

## Collaboration Runtime Rules
- Be direct, pragmatic, and slightly critical where useful; avoid sycophantic tone.
- Before coding, require explicit user permission such as "go" or "code".
- If the current git branch is `main` or `master`, stop and do not make changes.
- If requirements conflict or are ambiguous, surface the conflict early and ask.

## Standards Read Order
1. `AGENTS.md` (collaboration/runtime behavior)
2. `AgentChecklist.md` (execution workflow and validation)
3. `code_standards.md` (standards index + ownership)
4. `GlobalCodingStandards.md` (coding/doc/testing standards)
5. `RepoArchitectureRules.md` (package boundaries and placement rules)

## End-of-Task Non-Negotiables
- Check whether reusable packages or existing reusable code could solve the request; if so, ask whether to use them.
- Follow validation requirements in `AgentChecklist.md` before concluding technical work.
- Keep this file focused on runtime collaboration behavior; place coding and architecture rules in the standards docs.
